# GTNH Journey 1.1.23 Scope

Target runtime: GT New Horizons 2.9.0-beta-2 with NotEnoughItems 2.8.111-GTNH.

## Release goal

Make Journey preserve real researched item identity and behave as a native NEI view for filtering/searching, without mutating NEI's global item universe.

## Required fixes

### 1. Mob spawner identity

- A Silverfish, Zombie, Cave Spider, or modded mob spawner must never be persisted or reissued as the default Pig spawner.
- Preserve NEI 1.7.10 spawner identity using the entity numeric ID carried in ItemStack metadata when that representation is available.
- For a placed vanilla mob spawner researched through Debug Researcher Tool BLOCK/AREA_16, read the TileEntityMobSpawner entity name and resolve it through EntityList to the exact numeric entity ID before creating the Journey research candidate.
- Cover both direct observed ItemStack acquisition and placed-block migration/research paths.
- Unknown/unresolvable entity identity must fail closed. It must not silently become metadata 0 / Pig.
- Existing legacy `minecraft:mob_spawner` entries with meta 0 and no identity-bearing data remain invalid migration candidates and must not recreate Pig as a substitute for an unknown mob.
- Restart, full sync, snapshot, restore, delete/undo and retrieval must preserve the same spawner entity identity.

### 2. NEI Item Subsets parity

- The top Item Subsets widget must affect Journey modes the same way it affects the normal NEI item panel.
- Journey must honor the real `codechicken.nei.SubsetWidget` filter instead of explicitly excluding it.
- Hide/show/show-only changes in Item Subsets must refresh the currently owned Journey panel immediately.
- The subset mask is presentation-only: it may hide a researched entry from the panel but must never delete or mutate authoritative Journey research.
- Item Subsets must compose with Journey mode and search as an intersection: `researched/newest/delete set ∩ active subset visibility ∩ active search filter`.
- Returning to ALL/normal NEI must restore normal NEI ownership and filtering with no stale Journey list.

### 3. Native GTNH NEI search semantics

Journey must use the search filter produced by the target NEI `SearchField` / `SearchTokenParser`; Journey must not implement a second parser.

Required parity includes every search provider and operator enabled by the user's NEI configuration, including the stock GTNH prefixes such as:

- `@` mod name search;
- `#` tooltip search;
- `$` Ore Dictionary search;
- `&` item/registry identifier search;
- `%` subset-name search;
- chemical/formula provider and any other provider registered by the target GTNH/NEI runtime;
- `|` OR expressions;
- extended/regex search modes and wildcard behavior supported by the configured NEI pattern mode;
- prefix remapping and provider SearchMode (`ALWAYS`, `PREFIX`, `NEVER`).

The implementation must delegate to the live NEI parser/configuration so future provider additions and user prefix remaps do not require Journey-side syntax changes.

### 4. Search/subset lifecycle regressions

- Preserve the existing hidden-search protection: a search field that is not visible in the current GUI must not leak stale text into Journey.
- Search text changes must refresh Journey while Journey owns the panel; no J/N toggle should be required.
- Item Subsets visibility changes must refresh Journey while Journey owns the panel; no J/N toggle should be required.
- RESEARCHED, NEWEST and DELETE modes must all use the same NEI filtering semantics.
- Filtering must only change presentation. Research keys, templates, timeline order and recovery snapshots remain authoritative and untouched.

## Acceptance matrix

The release is not complete until all of these pass on the target pack:

1. Add/research Silverfish Spawner, restart, retrieve it, place it: it remains Silverfish.
2. Repeat for at least Pig, Zombie, Cave Spider and one modded living entity with a valid EntityList ID.
3. Scan a placed Silverfish spawner with Debug Researcher Tool BLOCK and AREA_16: Journey receives Silverfish identity, not Pig.
4. Hide a mod/category through Item Subsets while Journey is active: matching Journey entries disappear only from the panel and return when unhidden.
5. Use Item Subsets show-only while Journey is active: the Journey panel becomes the intersection with that subset.
6. Verify `@`, `#`, `$`, `&`, `%` against known researched entries with each provider configured in PREFIX mode.
7. Verify at least one `|` OR query and the configured extended/regex mode.
8. Remap an NEI prefix in settings and verify Journey follows the remap without a Journey config change.
9. Hide the search field / switch to a GUI where it is not visible and verify stale search text does not filter Journey.
10. Switch back to ALL/normal NEI and verify the normal NEI list, subset state and search state are intact.

## Non-goals

- Do not maintain a Journey-specific copy of NEI's search grammar.
- Do not treat subset visibility as research deletion.
- Do not rewrite NEI's global item universe to make Journey filtering work.
- Do not create Pig as a fallback for an unknown spawner identity.
