# GTNH Journey 1.1.23 Research Identity + NEI Parity Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship GTNH Journey 1.1.23 with exact mob-spawner identity and make Journey RESEARCHED/NEWEST/DELETE behave like a native GTNH NEI view for Item Subsets and the complete NEI search grammar.

**Architecture:** Keep Journey research persistence/server authority unchanged. Journey continues to own only the displayed item-panel list while active, but every presentation refresh intersects the Journey-owned set with the live NEI filter providers. Do not reimplement NEI search syntax. Treat `ItemList.updateFilter.restart()` as the canonical NEI filter-invalidation signal so SearchField, Item Subsets, config-driven provider changes, and future NEI filters can invalidate Journey through one bridge. Preserve the existing hidden-search visibility guard and never let presentation filters mutate research. For mob spawners, preserve the entity numeric ID carried in item metadata and repair the placed-block research path by deriving that ID from the spawner tile entity instead of accepting metadata 0 / Pig fallback.

**Tech Stack:** Java 8 source compatibility on GTNH 1.7.10 runtime, GTNH convention Gradle build on Java 25 CI, Sponge Mixin, Forge/FML, NotEnoughItems 2.8.111-GTNH, JUnit 5.

**Spec:** `docs/v1.1.23-scope.md`

### Step 4: Implement minimal revision state

Create a small client-side monotonic revision holder. It must contain no ItemStack/research state and must be safe to read from the client tick.

Preferred shape:

```java
public final class JourneyNeiFilterRevision {
    private static long revision;

    private JourneyNeiFilterRevision() {}

    public static synchronized void invalidate() {
        revision++;
    }

    public static synchronized long revision() {
        return revision;
    }

    public static synchronized void reset() {
        revision = 0L;
    }
}
```

### Step 5: Bridge native NEI invalidation once

Mixin `RestartableTask.restart()` and, at method entry, identify only the canonical `ItemList.updateFilter` instance. When that instance restarts, increment `JourneyNeiFilterRevision`.

Do **not** intercept `loadItems` or `refreshItems` as independent Journey concepts. They already feed `updateFilter.restart()` in target NEI 2.8.111-GTNH.

Do **not** cancel native NEI behavior.

### Step 6: Feed the revision into JourneyNEIRefreshTracker

Add `seenNeiFilterRevision`. On END client tick:

```java
long filterRevision = JourneyNeiFilterRevision.revision();
boolean filterChanged = filterRevision != seenNeiFilterRevision;
```

Pass `filterChanged` into the decision table. In RESEARCHED/NEWEST/DELETE, it must choose `PANEL_REFRESH`; in ALL, leave native NEI to complete its own filter task.

Reset the revision tracker during session teardown together with `JourneyPanelController.clear()`.

## Task 6: Fix spawner identity at the placed-block boundary

**Files:**
- Create or move shared policy to: `src/main/java/dev/gtnhjourney/minecraft/MobSpawnerIdentityPolicy.java`
- Modify: `src/main/java/dev/gtnhjourney/debug/PlacedBlockResearchResolver.java`
- Remove or delegate: `src/main/java/dev/gtnhjourney/debug/MobSpawnerResearchIdentity.java`
- Modify tests from Task 5.

### Step 1: Make spawner identity a shared runtime policy

The old v1.1.12 helper was debug-only and therefore never protected the ordinary identity/retrieval path. Replace that half-integration with a shared policy that can:

1. identify a vanilla/NEI mob-spawner ItemStack;
2. resolve a spawner tile entity's entity name to the target runtime's numeric EntityList ID;
3. apply that ID to a defensive copy of the picked/fallback spawner ItemStack;
4. reject unresolved/non-positive identity instead of returning meta 0.

Do not encode a fixed mob-name table in Journey.

### Step 2: Special-case placed mob spawners before the generic block fallback

In `PlacedBlockResearchResolver.resolve(world, player, x, y, z, side)`:

- keep the existing generic pick-block strategy for ordinary blocks;
- when the target is a mob spawner, read the loaded `TileEntityMobSpawner` identity;
- resolve that entity through the live `EntityList` mapping;
- take the valid picked/fallback spawner stack and replace only its entity metadata with the resolved numeric ID;
- return `null` if identity cannot be resolved safely.

This prevents block metadata 0 from silently turning into Pig in NEI's spawner item implementation.

### Step 3: Keep direct acquisition exact

Do not normalize valid positive spawner metadata in `ItemStackKeyFactory`, persistence, or retrieval. The generic exact metadata pipeline should remain sufficient once the correct ItemStack reaches it.

## Regression constraints for every task

- Journey filtering is presentation-only. Never delete research because an NEI filter hides it.
- Journey must not add a second search grammar or fixed prefix table.
- Hidden search text must remain isolated when SearchField is not visible.
- Item Subsets must affect Journey exactly because it is a real NEI filter provider, not because Journey copies its hidden-items storage.
- Any NEI provider that invalidates `ItemList.updateFilter` should automatically refresh an active Journey view.
- Valid spawner entity metadata must survive research, sync, restart, snapshots, delete/undo/restore, retrieval, and placement.
- Unknown spawner identity must fail closed. Never substitute Pig.
- Returning to ALL must restore native NEI ownership without stale Journey state.
