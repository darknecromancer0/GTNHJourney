# GTNHJourney 1.1.0 World Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship GTNHJourney 1.1.0 with synchronous rotating world backups, an optional global Forge explosion blocker with throttled operator diagnostics, and `/journey cleanse` for removable negative potion effects including IC2 radiation.

**Architecture:** Keep the three safety features isolated from research/retrieval code. Backups are split into pure cadence/rotation policy plus a server-side writer; explosion cancellation is split into config/state, source naming, throttling and event handling; cleanse is a small player-only service. `CommandJourney` and `GTNHJourney` only compose/delegate.

**Tech Stack:** Java 8 source compatibility via GTNH build tooling, Minecraft/Forge 1.7.10, GTNH 2.9.0-beta-2 APIs, JUnit 5, Gradle/RetroFuturaGradle, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-28-v1.1-world-safety-design.md`

## Global Constraints

- Target version is exactly `1.1.0`.
- Base behavior from GTNHJourney 1.0.4 must remain unchanged outside the new safety features.
- Automatic world backups default to enabled, interval exactly 300 seconds, retention exactly 3.
- Backups must force-save first, then synchronously archive while the server thread is blocked.
- A failed new backup must never delete any previous successful backup.
- Backup archives must live outside the source world directory.
- Normal explosions default to enabled. `/journey explosions off` means cancel explosions globally.
- Explosion cancellation itself is never throttled; only chat diagnostics are throttled to one message per 5 seconds.
- `/journey cleanse` removes only currently active harmful potion effects and preserves positive effects and persistent non-potion systems.
- Existing Forge build, Spotless/checkstyle, version guard and artifact upload remain mandatory.

## Live validation after installing the JAR

The automated gate cannot prove filesystem timing or every GTNH explosion source. After CI green, validate in a copy of the GTNH 2.9.0-beta-2 instance:

1. Start world and wait just over 5 minutes; confirm one ZIP under `gtnhjourney-backups/<world>/`.
2. Run `/journey backup now` four times; confirm only newest three successful ZIPs remain.
3. Restore one ZIP into a copied save slot and load it.
4. Run `/journey explosions off`, ignite TNT, confirm no block/entity explosion effect and one operator diagnostic.
5. Trigger repeated TNT within 5 seconds; confirm every explosion is canceled but chat is throttled.
6. Trigger a GT machine/boiler explosion path where practical; confirm cancellation and best-effort source name.
7. Run `/journey explosions on`; confirm normal explosion behavior returns.
8. Apply IC2 radiation plus another negative potion and one positive potion; run `/journey cleanse`; confirm negative effects disappear, positive remains, and radiation can reappear if the radioactive source remains present.
