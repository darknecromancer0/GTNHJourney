# GTNH Journey 1.1.26 Sorting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the old NEWEST view with composable View × Group × Order × Latest presentation, preserve native GTNH NEI filtering/page behavior, move S/T beside native G/expand, and restore vanilla Up/Down chat history while keeping popup selection on Shift+Up/Down.

**Architecture:** Keep membership authoritative in the existing Journey/NEI filter pipeline, then pass surviving presentation entries through a new pure sort planner. Group, Order, and Latest are explicit independent client state, while favourite-add chronology and presentation activity use bounded server-authoritative data only where persistence/cross-session correctness requires it. UI changes are isolated to the NEI header widget/dropdown layer; retrieval/research identity code remains untouched.

**Tech Stack:** Minecraft 1.7.10, Forge/FML, GTNH 2.9.0-beta-2, NEI 2.8.111-GTNH, Java, JUnit 5, Sponge Mixin, Gradle/GTNH convention plugin.

**Spec:** `docs/superpowers/specs/2026-09-05-v1.1.26-journey-sorting-design.md`

## Global Constraints

- Target exactly GTNH 2.9.0-beta-2 / NEI 2.8.111-GTNH / Minecraft 1.7.10.
- Preserve J/F/C/D click semantics and all 1.1.25 research/retrieval/recovery/speed/explosion behavior.
- Native GTNH Item Subsets and SearchField grammar (`@`, `%`, `#`, and all installed operators) determine membership before Journey sorting.
- Activity-only reorder must never reset page 2+ to page 1; page may only clamp if page count shrinks.
- S/T belong in the far-right Journey service cluster beside native G/expand and must not overlap native NEI controls.
- Plain Up/Down always remain vanilla chat-history keys; popup navigation uses Shift+Up/Down only.
- Runtime, Gradle, and `mcmod.info` version must all be `1.1.26` before release artifact verification.

- [ ] **Step 4: Implement semantic classification**

- [ ] **Step 5: Implement planner**

Algorithm:

```java
List<GroupBucket> buckets = group(entries, groupMode);
Comparator<GroupBucket> base = orderComparator(orderMode);
if (latest) base = latestComparator().thenComparing(base);
buckets.sort(base);
for (GroupBucket bucket : buckets) bucket.sortMembers(memberComparator(groupMode, orderMode));
return flatten(buckets);
```

When `groupMode == NONE`, each entry is a one-item bucket, so J+L is pure activity order and never inherits a previous group.
