# GTNHJourney 1.1.26 Live Sorting/UI Regression Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the live 1.1.26 NEI regressions reported after sorting landed: page-label overlap, dropdown z/input leakage, unreliable sort-control clicks, C+L+N head ordering, and delayed C-issued research.

**Architecture:** Keep the existing View × Group × Order × Latest architecture and per-view state. Move only presentation ownership: left-side view buttons remain anchored after page-prev, while L/Group/Order are anchored from the right service zone so the native page label keeps a clear center. Split dropdown rendering into compact-button and overlay passes, and make the open popup own its rectangle before any item click can leak through. Latest keeps group movement, but when active also promotes the most recently active member to the head of its active group. C issuance becomes an authoritative research event on the server instead of relying on later inventory observation.

**Tech Stack:** Java 8 source compatibility, Minecraft 1.7.10, GTNH 2.9.0-beta-2, NEI 2.8.111-GTNH, JUnit 5, Gradle 9.3.1 CI on Java 25.

**Spec:** `docs/superpowers/specs/2026-09-05-v1.1.26-journey-sorting-design.md`, amended by the approved live-test behavior in this plan.

## Global Constraints

- Preserve independent Group/Order/L state for NEI/J/F/C/D exactly as implemented in `JourneySortState`.
- Native NEI filters and membership remain authoritative; this change is presentation/input/research timing only.
- Sorting controls must not overlap native page navigation, page label, search, Item Subsets, or G/expand.
- S/T hide before core view/sort controls collide with native UI.
- C issuance remains permission-gated and server-authoritative.
- Runtime version remains `1.1.26`.
