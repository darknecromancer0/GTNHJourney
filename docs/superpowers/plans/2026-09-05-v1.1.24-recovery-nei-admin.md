# GTNH Journey 1.1.24 Recovery, NEI and Admin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 1.1.24 with death-inventory recovery, generalized reversible admin actions, F/C NEI modes, native filter/page parity, global command hints, and debug-tool/spawner fixes.

**Architecture:** Preserve the 1.1.23 research journal unchanged. Add a separate persisted reversible action journal and a coordinator that merges research/action undo chronologically. Death recovery is an explicit keepInventory watchdog with standard+Baubles slot snapshots. NEI remains client-owned only in Journey modes, but filtering uses native representatives and C builds a native-universe-plus-Journey-extras list.

**Tech Stack:** Java 8 source compatibility, Forge/FML 1.7.10 events/networking, GTNH NEI 2.8.111-GTNH, JUnit 5 pure/contract tests, GTNH Gradle build.

**Spec:** `docs/superpowers/specs/2026-09-05-v1.1.24-recovery-nei-admin-design.md`

## Global Constraints

- Target GTNH 2.9.0-beta-2 and NEI 2.8.111-GTNH.
- No hard runtime dependency on optional integrations; GregTech/Baubles access is narrow and fail-closed.
- Never overwrite an occupied post-death inventory slot during recovery.
- Existing 1.1.23 research data and undo journal remain backward-compatible.
- All new command mutations require the same integrated-owner/operator permission as existing safety/speed mutations.
