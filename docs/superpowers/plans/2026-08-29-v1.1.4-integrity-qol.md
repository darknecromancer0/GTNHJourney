# GTNHJourney 1.1.4 Integrity and QoL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver GTNHJourney 1.1.4 with research-preserving migration/presentation, Botania transient-state deduplication, backup completion feedback, Shift+RMB inventory filling, working live command hints, richer diagnostics, and safe session-scoped server tick acceleration.

**Architecture:** Preserve the existing server-authoritative research/network model. Fix each regression at its narrow boundary: semantic normalization in `minecraft/`, fail-open presentation in `nei/`, one new server request for inventory fill, backup completion events in `backup/`, robust chat-input access in `client/`, and an isolated tick-cadence adapter in `time/`. Any uncertain migration/presentation/runtime integration fails toward data preservation, visibility, or `1x` speed.

**Tech Stack:** Java 8 source compatibility, Minecraft/Forge 1.7.10, GTNH 2.9.0-beta-2 runtime, NEI 2.8.111-GTNH, Gradle 9.3.1 CI on Java 25, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-08-29-v1.1.4-integrity-qol-design.md`

## Global Constraints

- Base commit: `42cd9070eaa6fd47b2e9c9abe331da6ff26b2aeb` plus the approved 1.1.4 spec commit on `feature/v1.1.4-integrity-qol`.
- Target pack: GTNH `2.9.0-beta-2`, Minecraft/Forge `1.7.10`, NEI `2.8.111-GTNH`.
- Preserve existing Journey research/recovery/snapshot/network semantics unless the spec explicitly changes them.
- Never discard a valid persisted research entry because optional migration/reconstruction fails.
- Never manually extra-tick arbitrary tile entities for speed acceleration.
- Every production behavior change starts from a failing regression test.
- Do not mark the release complete until exact-head GitHub Actions is green.
