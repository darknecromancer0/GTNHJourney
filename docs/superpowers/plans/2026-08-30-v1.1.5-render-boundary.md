# v1.1.5 Render Boundary Crash Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent the GTNH 2.9.x client from crashing when WR-CBE enters `RenderWorldLastEvent` while the shared Minecraft 1.7.10 Tessellator is still drawing, without changing normal rendering or the 1.1.4 QoL features.

**Architecture:** Add a tiny client-side render-boundary recovery helper and an optional `@Pseudo` mixin for WR-CBE. At the start of `WRCoreEventHandler.onRenderWorldLast`, inspect the vanilla Tessellator drawing flag through a Mixin accessor; only when it is already active, finish that dangling batch before WR-CBE starts its own CCRenderState batch. Keep the compatibility patch client-only and fail-open when WR-CBE is absent.

**Tech Stack:** Minecraft 1.7.10, Forge 10.13.4.1614, UniMixins/Mixin, JUnit 5, Gradle 9.3.1/JDK 25 CI.

**Spec:** User crash logs from 2026-08-30 and existing v1.1.4 behavior are authoritative. The FML listener dump places WR-CBE at failing listener index 17 after another world-render listener and the exception is `Already tesselating!` from `RenderWirelessBolt.render`.

## Global Constraints

- Preserve all v1.1.4 Journey integrity, backup, hint, inventory-fill, Botania dedup and time-speed behavior.
- Do not globally call `Tessellator.draw()` every frame; recover only when `isDrawing == true` at the WR-CBE event boundary.
- Do not hard-depend on WR-CBE classes at compile time; use an optional string-target `@Pseudo` mixin.
- Keep the recovery client-only.
- Release as 1.1.5 with runtime, mcmod, Gradle and README metadata aligned.
