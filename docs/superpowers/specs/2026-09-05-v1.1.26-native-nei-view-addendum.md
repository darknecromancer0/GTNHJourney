# GTNH Journey 1.1.26 Native NEI View Addendum

This addendum extends `2026-09-05-v1.1.26-journey-sorting-design.md` and supersedes only statements that said ALL/native NEI does not own sort state.

## Explicit NEI view

The header contains an explicit **NEI** view button in addition to J/F/C/D.

- The button label is `NEI`, using a slightly wider header button than the 16px single-letter buttons so the text remains readable.
- Activating NEI selects `JourneyViewState.Mode.ALL`.
- NEI remembers its own Group / Order / L settings independently from J/F/C/D.
- J/F/C/D settings never leak into NEI, and NEI settings never leak back into J/F/C/D.

## Native input semantics are authoritative

NEI view is never a Journey issuance view.

- `JourneyNEIInputHandler` must not consume ordinary item-panel clicks in Mode.ALL.
- Recipe/usage/native cheat behavior remains whatever the installed GTNH NEI defines.
- Journey sorting may change presentation order only; it must not change item click meaning.
- Alt favourite gestures do not run in NEI view.

## Zero-transform fast path

For NEI with:

- Group=None;
- Order=None;
- L=off;

the Journey panel controller releases ownership and lets native NEI publish/manage the item panel directly.

This is the strongest compatibility path and must remain identical to ordinary GTNH NEI.

## Sortable NEI path

When any NEI Group / Order / L transform is active:

1. source content is `ItemList.items` (native NEI universe only, no Journey-only C variants);
2. the real active GTNH NEI filter providers determine membership first, including Item Subsets and SearchField operators such as `@`, `%`, `#` and every installed native operator;
3. only surviving native items are converted to `JourneySortEntry` presentation metadata;
4. Group / Order / L reorders those survivors;
5. ItemPanel is published with page retention;
6. input remains native because Journey input handling returns false for Mode.ALL.

Sorting may never reintroduce an item rejected by a native filter.

## NEI sorting semantics

- N/M/T/K and A apply normally to the complete filtered native set.
- U ranks researched items/families by unlock chronology; native items with no Journey unlock remain behind items with a known unlock sequence and retain deterministic native order amongst themselves.
- L ranks identities/families with known Journey/presentation activity first; native items with no activity remain deterministically ordered behind active ones.
- F+ is unavailable in NEI.
- Turning all transforms off immediately restores the zero-transform native fast path.

## UI placement

The view strip begins with a slightly wider `[NEI]` button, followed by J/F/C/D and the compact sort controls. S/T remain in the far-right service cluster beside original GTNH G/expand.

At narrow widths the layout may compact/hide lower-priority service controls, but `[NEI]`, current view access, native page controls, search, Item Subsets and G/expand must never overlap.

## Release-blocking tests

- NEI + no transforms releases to native NEI.
- NEI + N/A/M/T/K/L uses the same native filter membership as ordinary NEI.
- Journey item input handler returns false in NEI view for LMB/RMB/Alt variants.
- Switching J(N+U+L) -> NEI(M+A) -> J restores each view's independent state.
- Switching all NEI transforms off returns to the native fast path.
- Page 2+ is retained for activity-only/sort refreshes unless the resulting filtered list has fewer pages.
- `[NEI]` is readable and non-overlapping; S/T remain beside G/expand.
