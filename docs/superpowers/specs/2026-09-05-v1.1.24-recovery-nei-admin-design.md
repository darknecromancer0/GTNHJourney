# GTNH Journey 1.1.24 Recovery, NEI and Admin Design

## Scope

Target remains GTNH 2.9.0-beta-2 / NEI 2.8.111-GTNH on Minecraft 1.7.10.

This release keeps every 1.1.23 research/persistence invariant and adds the following live-test requirements from 2026-09-05:

- Native NEI Item Subsets/Search parity for Journey presentation stacks.
- Preserve the current NEI page after issuing an item from page 2+.
- Global command suggestions for all slash commands, with Up/Down selection and Tab acceptance; Journey help and suggestion contracts must stay synchronized with real commands.
- Debug Researcher Tool: one physical Shift+RMB press cycles exactly one mode; targeted use must not fall through into a second no-target action.
- Placed mob spawners must research through BLOCK and AREA_16 with exact entity metadata.
- Favourite mode F uses directional gestures, never toggle semantics: Alt+LMB adds an exact researched state to F only from J or N; Alt+RMB removes an exact state only while viewing F. Repeating Alt+LMB on an already-favourited J/N entry is an idempotent no-op, not a removal.
- Ordinary item issuance is consistent across Journey-owned item views J/N/F/C: LMB gives one item, RMB gives one natural stack, Shift+RMB fills the main inventory. The two favourite gestures above intercept only their exact Alt+button combinations and do not change other clicks.
- Creative mode C displays the native NEI universe plus Journey-only exact variants, inserting Journey variants next to the matching native item/meta family. C uses the same Journey LMB/RMB/Shift+RMB issuance contract and is an owner/op debug give surface.
- Death inventory guard for keepInventory=true: snapshot main inventory, armor and Baubles immediately before death; compare after respawn; if a loss is detected, warn in chat and retain a recoverable snapshot. `/journey return death inventory` restores missing pre-death contents non-destructively.
- General undo/redo must include reversible administrative actions without discarding the existing persisted research undo journal. Add category-specific undo/redo for speed, explosions, favourites and death inventory restore.
- `/journey undo [n]` and `/journey redo [n]` accept arbitrary counts clamped to the existing safety maximum.
- `/journey speed default` restores MACHINES 1x and is reversible.
- Machine-only acceleration is safety-capped at 16x. Extra TileEntity acceleration must never stop in the middle of a global pass because partial passes can advance GT power producers/buffers farther than downstream consumers. Whole-world acceleration may retain 32x/64x/128x where the server cadence adapter supports it.
- `/journey explosions machines on|off|status` controls GregTech machine explosions only. `/journey explosions default` restores both global explosions and GregTech machine explosions to on. These changes are reversible.
- Automatic Journey recovery snapshots are stored outside the world save tree under the instance-level `gtnhjourney-recovery` archive. `/journey snapshot latest return` restores the Journey research list from the newest valid external snapshot for the current world/player, skipping corrupt newer files. It does not overwrite the player's live inventory.
- Invalid Journey syntax must use vanilla red command errors with scope-local suggestions instead of dumping the entire Journey help page.

## Death recovery safety

Forge `LivingDeathEvent` is the pre-death capture boundary. Capture only when the server gamerule `keepInventory` is true. The comparison is delayed until the respawned player has ticked so late inventory-copy handlers have completed.

The recovery payload stores exact defensive copies of:

- `InventoryPlayer.mainInventory`
- `InventoryPlayer.armorInventory`
- Baubles inventory obtained reflectively from `baubles.api.BaublesApi#getBaubles(EntityPlayer)` when available

Baubles Expanded 2.2.21-GTNH stores its inventory outside player.dat, so it must be captured explicitly.

Restoration is non-destructive. Matching current stacks are kept. Missing pre-death stacks are returned to their original empty slot where possible; otherwise to ordinary inventory, and only as a last resort dropped at the player. Existing post-death contents are never overwritten.

## Reversible action history

Do not migrate or rewrite existing `JourneyRecoveryData` research transactions. Add a second persisted bounded journal for non-research reversible actions. General undo/redo peeks both journals and applies whichever top entry has the newest original action timestamp. Category undo/redo operates only on the action journal.

Action kinds in 1.1.24:

- SPEED
- EXPLOSIONS
- FAVOURITE
- DEATH_INVENTORY_RETURN

Every action stores enough before/after payload to replay and reverse safely. Failed/no-op changes are never journaled.

## Explosion semantics

Global `explosions off` continues to cancel Forge explosions. Machine-only control uses the GregTech public static `gregtech.api.GregTechAPI.sMachineExplosions` through a narrow reflective adapter so Journey does not add a hard compile-time GT dependency. This is the correct interception point because GT removes the machine before creating the ordinary world explosion.

## Speed safety

`machines` mode directly invokes extra updates on already-loaded tickable TileEntities while the ordinary server cadence remains 20 TPS. Its maximum selectable multiplier is 16x.

The accelerator snapshots the loaded TileEntity lists for every loaded world and performs complete global extra passes. The runtime deadline is checked only between complete passes. It is forbidden to abort inside a world's TileEntity list because that can accelerate a battery/buffer or cable network without giving downstream machines the same number of extra updates.

`world` mode accelerates the complete server cadence and therefore preserves normal relative ordering between energy networks, machines, entities and other world systems. Its existing 1/2/4/8/16/32/64/128 range remains available when supported.

## External Journey recovery archive

Automatic Journey snapshots are duplicated outside `saves/` in:

`<instance>/gtnhjourney-recovery/<world>/research-snapshots/`

The archive is independent of `WorldSavedData`, uses compressed NBT plus atomic replacement, and is bounded to 50 MiB by pruning oldest snapshots.

`/journey snapshot latest return` reads newest-first for the current world and player, skips corrupt/incompatible candidates, validates the complete research state against the current runtime registry, creates an in-world safety snapshot of the pre-return state, then replaces the Journey research list transactionally. Player inventory NBT may remain present in the archive for separate disaster recovery, but this command never applies it.

## NEI modes

Modes are mutually exclusive: ALL, RESEARCHED (J), NEWEST (N), FAVOURITE (F), CREATIVE (C), DELETE (D).

F is the researched set filtered by the persisted favourite keys, using J chronology unless future requirements explicitly request a second order.

C begins from a copy of NEI `ItemList.items`. Journey exact variants missing from the native list are grouped by item registry id + metadata and inserted directly after the corresponding native family anchor. Native entries remain in native NEI order. Search and subset filters are applied using a native representative when one exists, preventing SubsetWidget's out-of-universe fallback from broadening results.

Final click contract:

- J/N: Alt+LMB means add to F and consumes only that click.
- F: Alt+RMB means remove from F and consumes only that click.
- J/N/F/C: plain LMB gives one item, plain RMB gives one natural stack, Shift+RMB fills the main inventory.
- Alt+LMB in F and Alt+RMB in J/N are not favourite actions and must not silently toggle state.

## Command/help invariants

The server command tree is authoritative. Client overlay suggestions must consume vanilla/server Tab completion rather than duplicate Journey command names. Journey-specific help text must have a regression contract covering every top-level Journey subcommand and all new documented subcommands.

Unknown roots and invalid nested values throw vanilla `CommandException`-style red errors. The error must suggest only the valid choices at the current scope, for example `/journey explosions [status|on|off|default|undo|redo|machines]` or `/journey explosions machines [status|on|off]`, rather than printing the full Journey help page.
