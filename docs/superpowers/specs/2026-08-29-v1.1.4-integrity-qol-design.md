# GTNHJourney 1.1.4 Integrity and QoL Design

## Goal

Ship a regression-focused GTNHJourney 1.1.4 release that restores trustworthy Journey visibility/persistence, deduplicates transient Botania state, improves backup lifecycle feedback and safety, adds Shift+RMB inventory filling, repairs command hints in GTNH, improves diagnostics, and adds safe global time acceleration.

## Release base and compatibility

- Base commit: `42cd9070eaa6fd47b2e9c9abe331da6ff26b2aeb` from `feature/v1.1.3-transient-dedup`.
- Implementation branch: `feature/v1.1.4-integrity-qol`.
- Target pack remains GTNH `2.9.0-beta-2` on Minecraft/Forge `1.7.10`.
- Existing Journey research, recovery, snapshots, NEI modes, retrieval semantics, world-safety commands, and GT semantic policies must remain compatible unless explicitly changed below.
- This release prioritizes preservation over cleanup: an uncertain migration must preserve a researched state rather than silently discard it.

## 1. Research integrity and missing-item regression

### Observed symptom

Live testing reported researched items such as Lithium, Battery Alloy Ingot, Battery Alloy Plate, and High Voltage Steam Turbine disappearing from Journey. The same session later produced fresh unlock notifications for several of those items, proving that at least some previously-known research was no longer visible/recognized.

Diagnostics simultaneously showed a very large authoritative research set and a very small panel-visible set. No active deletion history explained the loss.

### Required behavior

Journey must never lose a valid researched entry merely because semantic migration, ItemStack reconstruction, optional-mod integration, client presentation, or a third-party NEI filter fails.

Persistence migration remains fail-closed with respect to unsafe normalization but fail-safe with respect to preservation:

1. Read the stored item id/meta/canonical NBT/template.
2. Attempt semantic normalization and reconstruction.
3. If reconstruction or optional policy application cannot prove a safe migrated result, preserve the validated persisted key/template.
4. Never silently omit a valid persisted entry only because a newer runtime policy cannot reconstruct it.
5. Known duplicate normalization may merge two keys only when the policy proves they represent the same semantic item state.

Client publication must similarly avoid accidental mass-hiding:

- Journey continues to honor the visible NEI search field and compatible active item filters.
- Hidden/stale filter providers must not silently hide Journey entries.
- A filter provider that throws must not hide the tested stack; the failure is diagnostic-only.
- Search/filter isolation must be covered by regression tests using large Journey lists and stale provider state.
- A complete client sync must never be replaced by an incomplete epoch.

### Regression targets

Add explicit tests covering ordinary GregTech research that is not special charge/tool state, including representative `gregtech:gt.metaitem.01` and `gregtech:gt.blockmachines` entries. Tests must prove round-trip persistence and panel eligibility do not mutate or drop these entries.

## 2. Botania transient-state deduplication

### Special flowers

`Botania:specialFlower` research identity must preserve the flower type but ignore transient runtime counters that do not describe a different retrievable item.

For passive flowers such as Daybloom:

- Preserve `type`.
- Remove `passiveDecayTicks` from research identity and stored retrieval template.
- Merge historical states that differ only by `passiveDecayTicks` into one canonical entry during migration.
- Preserve one chronology position for the merged entry using the newest/most recently active equivalent position where the existing migration accumulator can do so safely.

The policy must apply by verified Botania registry/runtime semantics, not by blanket removal of arbitrary NBT keys from unrelated items.

### Wand of the Forest

Wand color/configuration that describes the actual item remains semantic.

Temporary block binding coordinates such as `boundTileX`, `boundTileY`, and `boundTileZ` must not create new Journey research states. Historical variants differing only by current binding coordinates must merge.

### Other Botania items

Do not broadly strip unknown Botania NBT. Existing magnet-ring cooldown normalization remains intact. Any additional transient key must be explicitly proven before normalization.

## 3. Backup lifecycle parity and chat feedback

### Safety model

Keep the current native-like asynchronous backup architecture:

1. Force-save player data.
2. Force-save loaded world/chunk data.
3. Wait for threaded file I/O to finish.
4. Create the archive in the existing Journey backup root.
5. Prevent overlapping backups.
6. Preserve successful backup rotation semantics and temporary-file safety.
7. Restore any temporary save-suppression state reliably on success, failure, and shutdown.

World backup code must not mutate Journey research, recovery history, or snapshots.

### Completion notification

Automatic and manual backups must surface completion to chat after the background worker actually finishes.

Successful example:

`[Journey] Backup completed: <archive> (<duration>)`

Failure example:

`[Journey] Backup failed safely: <reason>`

The automatic ticker must not discard `pollCompletion()` results. Notifications should go to online integrated-server owner/operators rather than indiscriminately broadcasting implementation details on a public server.

### Research persistence verification

Add tests/contracts proving backup preparation forces the world save path that contains Journey `WorldSavedData` before archive creation. Backup completion must not require a Journey research rescan or reload.

### Native-like behavior

Do not replace the asynchronous writer with a new backup subsystem. Changes should reduce divergence from GTNH/ServerUtilities lifecycle behavior where compatible, especially around save suppression restoration and shutdown.

## 4. Shift + Right Click inventory fill

### Existing semantics

- LMB in Journey view: retrieve one item.
- RMB in Journey view: retrieve one natural maximum stack.
- Existing Ctrl behavior outside Journey modes remains unchanged.

### New semantics

`Shift + RMB` on a researched Journey entry requests a server-authoritative `FILL_INVENTORY` action.

The server:

1. Resolves the exact researched `ResearchKey`/fingerprint.
2. Reconstructs the same semantic retrieval template used by normal Journey issuance.
3. Fills every eligible empty slot of the player's main inventory with one natural maximum stack of that item.
4. Does not overwrite occupied slots.
5. Does not fill armor slots, crafting-grid slots, or unrelated container inventories.
6. Uses the item's real max stack size, including `1` for non-stackable items.
7. Performs the fill in one server request rather than sending many client retrieve requests.
8. Calls container change detection once after the operation.
9. Records one Journey retrieval/activity touch for the selected research entry.

Delete mode continues to own its clicks and must not invoke fill behavior.

## 5. Command hint repair

### Existing intent

GTNHJourney already has a shared `JourneyCommandSuggestions` source and a client chat overlay. Live testing shows the visible suggestion UI does not appear reliably in the current GTNH client stack.

### Required behavior

Typing `/journey` or `/journey <prefix>` into chat must display live suggestions above the chat input without requiring Tab.

The implementation must:

- Keep `JourneyCommandSuggestions` as the canonical suggestion source shared with tab completion.
- Avoid relying on a single brittle reflection assumption for `GuiChat` input access.
- Support the actual GTNH/Angelica GUI event path used by 2.9.0-beta-2.
- Fail harmlessly if a third-party chat GUI is incompatible.
- Never interfere with normal chat typing, history, tab completion, or command submission.

Add runtime diagnostics for overlay registration, chat-input resolution, last suggestion count, and reflection/fallback failures.

## 6. Diagnostic dump improvements

`/journey dump` must become sufficient to diagnose disappearing research without manually decoding registry meta values.

Add at least:

- Client mirror stack count.
- Server authoritative research count.
- Server syncable count and server-only oversized count where available.
- Current Journey mode.
- Current visible NEI search text where safely accessible.
- Active Journey-applied NEI filter provider class names/count.
- Panel authoritative/semantic/visible counts.
- Display name beside each reconstructable research key.
- Explicit marker for unavailable/reconstruction-failed entries.
- Command-hint overlay diagnostic state.
- Backup running/last-result/last-duration state.

Diagnostics must be read-only. A broken third-party display-name lookup or filter provider must not make `/journey dump` fail.

## 7. Global time acceleration

### User-facing commands

Add:

- `/journey speed` or `/journey speed status`
- `/journey speed 1`
- `/journey speed 2`
- `/journey speed 4`
- `/journey speed 8`

Default is `1x`.

Changing speed requires integrated-server owner/operator permission. Reading status may be allowed to ordinary players.

### Semantics

Acceleration must increase the cadence of normal authoritative server/world ticks rather than manually calling arbitrary tile entities multiple times.

The target multipliers correspond to approximate server tick targets:

- `1x` = 20 TPS
- `2x` = 40 TPS
- `4x` = 80 TPS
- `8x` = 160 TPS

This should naturally accelerate systems that advance through normal server/world ticks, including GregTech machines, Botania flowers, furnaces, fluids, redstone, scheduled ticks, and other compatible production systems.

### Safety constraints

- Never implement acceleration by directly invoking `TileEntity.updateEntity()` multiple times from Journey.
- Keep the normal tick ordering intact.
- Do not accelerate wall-clock-based Journey backup cadence.
- Do not accelerate backup ZIP workers, recovery retention clocks, or notification throttles that intentionally use wall time.
- Speed state is session-scoped and resets to `1x` when the server/world session ends.
- If the runtime hook needed for safe tick cadence adjustment is unavailable or incompatible, fail closed to `1x` and report that acceleration is unsupported instead of installing an unsafe fallback.
- `8x` is the maximum supported value in 1.1.4.

## 8. Component boundaries

Prefer focused additions over expanding existing large classes.

Expected areas:

- `minecraft/`: Botania semantic/transient normalization.
- `persistence/`: safe migration/merge behavior only where required.
- `nei/`: filter isolation and Shift+RMB input policy.
- `network/`: one new inventory-fill request path and server handler.
- `backup/`: completion event/result surfacing and lifecycle parity tests.
- `client/`: robust command-hint input access and diagnostic state.
- `diagnostics/`: expanded dump fields.
- `time/` or similarly focused package: session speed state and safe runtime tick-rate adapter.
- `command/`: speed command parsing/permission/help/tab-completion glue.

Do not place feature logic directly into `GTNHJourney` beyond composition/registration.

## 9. Failure handling

- Persistence uncertainty preserves data.
- Presentation/filter uncertainty preserves visibility where possible and increments diagnostics.
- Botania dedup strips only explicitly verified transient keys.
- Backup failure never removes previous successful archives and always restores save state.
- Inventory fill failure issues no partial client-side illusion; the server remains authoritative.
- Command-hint failure never breaks chat.
- Tick acceleration incompatibility returns to `1x`.
- Optional-mod `RuntimeException`/`LinkageError` boundaries remain isolated and fail safely.

## 10. Testing strategy

Implementation follows TDD. Every subsystem change starts with a failing regression test.

Required coverage includes:

1. GregTech ordinary-item persistence round trip for lithium/battery-alloy-style metaitems and a machine/blockmachines entry.
2. No destructive fallback when persisted semantic reconstruction fails.
3. Daybloom `passiveDecayTicks` variants collapse into one research identity/template.
4. Different Botania special-flower `type` values remain distinct.
5. Wand binding coordinates are transient while semantic wand configuration remains distinct.
6. Hidden/stale NEI providers cannot mass-hide Journey entries.
7. Visible search/filter behavior still works.
8. Incomplete sync epochs cannot replace the last complete client mirror.
9. Automatic backup completion result is surfaced rather than discarded.
10. Backup preparation flushes player/world data before archiving and restores save suppression on every completion path.
11. Shift+RMB maps to one fill request; normal RMB remains one stack.
12. Server inventory fill touches only eligible empty main-inventory slots and respects max stack size.
13. Delete mode blocks retrieval/fill fallthrough.
14. Command suggestions appear through the supported client chat path and diagnostic counters record failure paths.
15. Diagnostic dump additions cannot crash on unavailable stacks/providers.
16. Speed command accepts only `1`, `2`, `4`, `8` and enforces permissions.
17. Runtime speed adapter changes supported cadence without manually extra-ticking tile entities.
18. Unsupported speed adapter fails to `1x`.
19. Backup cadence remains wall-clock based while speed > 1x.
20. Full existing Journey test suite and CI remain green.

## 11. Live validation checklist

Before 1.1.4 is called complete, test in a copied GTNH 2.9.0-beta-2 world:

1. Confirm previously researched Lithium, Battery Alloy Ingot/Plate, and HV Steam Turbine remain visible across save/quit/reload.
2. Unlock/use Daybloom over time and verify exactly one Daybloom research entry remains.
3. Bind/rebind Wand of the Forest and verify binding coordinates do not create duplicates.
4. Run a manual and automatic backup; verify both completion messages and restore one ZIP in a copied world slot.
5. Use Shift+RMB on stackable and non-stackable researched entries; verify only empty main-inventory slots fill.
6. Type `/journey`, `/journey b`, and `/journey speed `; verify live suggestions.
7. Run `/journey dump` and verify client/server/filter/display-name diagnostics are present.
8. Test `speed 2`, `4`, and `8` with a GregTech machine, furnace, Botania flower, and fluid/redstone system. Confirm no duplicate processing or obvious tick-order corruption.
9. Leave speed at `8x` long enough to cross a backup due time and confirm backup cadence follows wall clock rather than accelerated world ticks.
10. Save and quit, reopen, and confirm speed resets to `1x` and Journey research is intact.
