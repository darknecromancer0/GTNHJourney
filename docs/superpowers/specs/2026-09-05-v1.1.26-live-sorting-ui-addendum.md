# GTNH Journey 1.1.26 Live Sorting/UI Addendum

This addendum supersedes the conflicting parts of `2026-09-05-v1.1.26-journey-sorting-design.md` after live testing of 1.1.26. All other 1.1.26 invariants remain in force.

## Header geometry

The native NEI page indicator owns the center region between page navigation controls.

- `NEI/J/F/C/D` remain the left Journey view zone.
- `L/Group/Order` are right-anchored as the core sorting zone rather than appended directly after `D`.
- The sorting zone must not overlap the native page number.
- `S/T` remain optional service controls next to native `G` where space permits.
- When width becomes insufficient, `T` then `S` are removed before core view/sort controls are allowed to collide with native UI.

## Dropdown overlay and input ownership

An open Group/Order menu is a real top-layer popup.

- Compact selector buttons render in the ordinary Journey header pass.
- Open menu options render in `postRenderObjects`, above NEI item cells.
- The popup rectangle owns clicks, including gaps between its option rows.
- Any Journey-owned header or popup click cancels NEI's pending item-panel mouse-down state so mouse-up cannot issue the item underneath.
- A click outside an open popup may close it, but the same popup-selection click must never propagate into an underlying NEI item.

## Latest inside an active group

The live-test interaction model supersedes the earlier rule that `N + L` must preserve the complete internal native order.

When `L` is enabled with any non-None Group:

1. the group itself is ranked by the most recent activity of its members, as before;
2. the member with the highest activity sequence is promoted to the first position inside that group;
3. all remaining members retain their normal deterministic group/member order relative to one another.

For `N + L`, this means a freshly issued Water Cell is shown first, followed immediately by the remaining Fluid Cell family in native NEI order.

When `L` is disabled, `N` remains strict native NEI member order with no activity promotion.

With Group=None, `L` remains pure individual activity ordering.

## Creative issuance immediately researches the issued identity

The earlier presentation-only C rule is superseded.

After a successful server-authoritative C issuance:

- the exact issued `ItemStack` identity is observed immediately through the normal authoritative research path;
- a newly valid identity is added to Journey research/J immediately and uses the normal unlock synchronization/notification path;
- no later inventory interaction is required to make the issued identity researched;
- the successful issue still records C presentation activity for L ordering;
- permission, payload validation, exact NBT/meta identity, stack amount and fill-inventory semantics remain unchanged.

The old `CreativeIssueResearchSuppressor.mark(...)` policy is therefore not part of successful C issuance anymore.

## Per-view memory

No change: NEI/J/F/C/D continue to remember Group/Order/L independently for the client session.
