# GTNH Journey 1.1.6 live test

This pass verifies that Journey world backups never disable normal Minecraft world saving.

## Backup save-safety

1. Start an existing world and run `/journey backup status`.
2. Make a small visible world change, then run `/journey backup now`.
3. While the background ZIP is still running, keep playing and make another visible change.
4. Wait for the Journey backup-complete chat message.
5. Exit normally and reload the world.

Expected:

- Journey never sets `WorldServer.levelSaving` to the save-disabled state;
- normal world saves remain enabled during the whole backup lifecycle;
- the pre-backup flushed world is copied to an isolated staging snapshot before background compression starts;
- the background worker archives staging files, not the live save directory;
- the staging snapshot is removed after completion or a handled failure;
- both visible changes still exist after reload.

## Recovery archive sanity

Open the generated ZIP without extracting it over a live world.

Expected:

- the archive contains one top-level folder with the real save name;
- that folder contains `level.dat` and the expected world/dimension files;
- no `.staging` directory is stored in the archive.

## Regression smoke

- WR-CBE world rendering no longer crashes with `Already tesselating!`.
- Journey J/N research views and retrieval still work.
- `/journey speed status` still defaults to 1x after restart.
