# GTNH Journey 1.1.5 live test

This pass specifically verifies the `Already tesselating!` client crash reported after 1.1.4 while preserving the 1.1.4 regression matrix.

## Setup

- GTNH 2.9.0-beta-2 Java 17-25 instance or the same newer 2.9.x runtime used for the crash report.
- Replace `gtnhjourney-1.1.4.jar` with `gtnhjourney-1.1.5.jar`; do not keep both JARs.
- Keep WR-CBE enabled.
- Use the same world that produced the crash when possible.

## Render-boundary regression

1. Enter the affected world and remain in the area where the crash occurred for at least several normal render cycles.
2. Exercise any visible WR-CBE wireless-bolt effect available in the world.
3. Open/close chat and use `/journey` command hints while world rendering continues.
4. Open JourneyMap and return to the world.
5. Leave the world back to the menu and re-enter once.

Expected:

- no `java.lang.IllegalStateException: Already tesselating!`;
- no crash from `RenderWirelessBolt.render` / `WRCoreEventHandler.onRenderWorldLast`;
- normal WR-CBE bolt rendering remains visible;
- no new client render exception is introduced by the recovery guard.

## 1.1.4 smoke regression

- Journey J/N views still populate and retrieval works.
- Shift+right-click inventory fill still works for a researched stackable state.
- `/journey speed status` works and 1x remains the default after restart.
- `/journey backup status` works and backup completion notification still appears after a completed backup.
- `/journey dump` writes a diagnostic dump.

## Failure capture

If the crash repeats, attach:

- the new `crash-*.txt`;
- `logs/fml-client-latest.log`;
- `logs/latest.log`;
- `/journey dump` from the same run when possible.
