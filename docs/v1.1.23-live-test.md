# GTNH Journey 1.1.23 live regression checklist

Target runtime:
- GT New Horizons 2.9.0-beta-2
- NotEnoughItems 2.8.111-GTNH
- Minecraft 1.7.10

This checklist is the final in-game gate for 1.1.23. Unit/contract tests and the Forge build are necessary but cannot fully emulate NEI client state, modded entity registration, placed tile entities, or real world migration data.

## 1. Mob spawner identity

1. Research/add a Silverfish Spawner.
2. Restart the client/server/world.
3. Retrieve it from Journey and place it.
4. Confirm it is still Silverfish and never falls back to Pig.
5. Repeat the same round trip for Pig, Zombie, Cave Spider, and at least one modded living entity with a valid EntityList numeric ID.
6. Use Debug Researcher Tool in BLOCK mode on a placed Silverfish spawner and verify Journey records Silverfish.
7. Use AREA_16 around multiple different spawners and verify each type remains distinct.
8. Delete/undo/restore a researched spawner state and verify the mob type remains exact.

Expected: unresolved/unknown spawner identity fails closed. Journey must never invent Pig as a substitute.

## 2. Native NEI Item Subsets

1. Open Journey RESEARCHED mode.
2. Hide a mod/category in Item Subsets.
3. Confirm matching Journey entries disappear from presentation only.
4. Unhide the subset and confirm the entries return without re-researching them.
5. Test Item Subsets show-only and confirm Journey becomes the intersection of the Journey set and the selected subset.
6. Repeat in NEWEST and DELETE.
7. Return to ALL and verify native NEI ownership, subset state, and normal item list remain intact.

Expected: Item Subsets never delete Journey research, templates, timeline state, snapshots, or deletion history.

## 3. Native SearchField / SearchTokenParser delegation

Journey must use the live GTNH NEI SearchField/SearchTokenParser output. It must not maintain a second prefix parser.

With known researched entries, verify the enabled/default providers:
- `@` mod-name search;
- `#` tooltip search;
- `$` Ore Dictionary search;
- `&` item/registry identifier search;
- `%` subset-name search;
- `=` chemical/formula search when enabled by the pack;
- `a|b` OR expressions;
- configured extended/regex/wildcard behavior.

Then:
1. Change one NEI provider between PREFIX / ALWAYS / NEVER and verify Journey follows it.
2. Remap one search prefix in NEI settings and verify Journey follows the remapped prefix with no Journey config change.
3. Move to a GUI/state where the SearchField is hidden and verify stale search text does not filter Journey.
4. Return to ALL and verify normal NEI search state is intact.

## 4. Page retention after grant

1. Open a Journey view with at least two pages.
2. Go to page 2 or later.
3. Grant/retrieve one item normally.
4. Confirm the item is granted and the Journey panel remains on the same page.
5. Repeat with Shift + RMB full-inventory grant if available for the selected item.

Expected: research/activity refreshes preserve the current page. Only an actual view/filter change may reset pagination.

## 5. CropsNH seed identity and maxima

1. Research a crop seed with stats 12/10/10.
2. Later obtain the same crop with 10/12/10.
3. Confirm Journey keeps one crop entry and its stored template becomes the per-stat maxima 12/12/10 rather than creating a duplicate.
4. Restart and verify the merged maxima persist.
5. Repeat with a third improvement to the remaining stat.

Expected: merge is scoped to the same crop identity only. Different crops must never merge.

## 6. Transient Water state cleanup

1. Reproduce/inspect Water variants that previously appeared with transient amount-only names such as `7950L Water`.
2. Confirm the transient amount-only NBT/name does not create separate research identities.
3. Confirm Water carrying unrelated meaningful NBT is not globally stripped or renamed.
4. Restart and verify no duplicate amount-only Water entries return from migration.

## 7. RandomThings Fertilized Dirt alias

1. Research the exact RandomThings fertilized dirt / tilled variant involved in the old duplicate.
2. Confirm the known `fertilizedDirt_tilled` state aliases to the intended obtainable identity instead of creating a useless duplicate.
3. Confirm unrelated blocks/items with similar names are untouched.

## 8. AREA_16 dropped-item recovery

1. Drop several items inside the AREA_16 cube, including at least one stack with meaningful metadata/NBT.
2. Include an item falling near an edge/void where container/block scanning would miss it.
3. Run Debug Researcher Tool AREA_16.
4. Confirm dropped EntityItem stacks are included in the scan summary and research candidates.
5. Retrieve the NBT-bearing test item and verify metadata/NBT survives Journey identity/template processing.
6. Confirm ordinary block and inventory scanning still works in the same pass.

Expected: dropped entities are queried once for the full AREA_16 bounds, not once per block position.

## 9. Research persistence / recovery regression

1. Restart after all tests above.
2. Verify researched entries, templates, newest order, and retrieval remain stable.
3. Exercise a safety snapshot plus delete/undo/redo on representative exact-NBT and exact-meta items.
4. Confirm no previously researched unrelated items disappear.

## Release decision

1.1.23 is releasable only when:
- the complete Gradle test suite passes;
- the Forge build passes on the exact release SHA;
- the generated runtime JAR reports version 1.1.23;
- the checklist above has no blocking regression on the target GTNH/NEI runtime.
